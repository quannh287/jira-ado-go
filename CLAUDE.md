# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Desktop app built with [MyGo](https://github.com/egoist/mygo) (`github.com/egoist/mygo` v0.4.8) using **native UI** (package `github.com/egoist/mygo/ui`): the interface is written in Go and drawn by MyGo on the GPU — no webview, HTML, JS, or frontend build. Pure Go module; no bun/npm. A one-way Jira→ADO sync tool, a native port of the Next.js app at `~/Development/OTHERS/jira-ado` (its engine is `app/api/sync/jobs/[id]/run/route.ts`).

## Commands

- `go tool mygo dev` — run the app with reload (CLI is pinned as a Go tool in `go.mod`)
- `go tool mygo build` — package the app into `build/`
- `CGO_ENABLED=0 go test ./...` — tests; single test: `CGO_ENABLED=0 go test -run TestMainFlow ./internal/app`
- `JIRA_ADO_DEMO=1 go tool mygo dev` — use the fake engine (no Jira/ADO calls) and seed demo jobs into an empty database
- `KEYCHAIN_TEST=1 go test ./internal/keychain` — opt-in test against the real OS keychain
- `go tool mygo vet ./internal/app` — MyGo-specific vet (stored build values, goroutine captures); takes a package dir, not `./...`

## Architecture

- **Packages**: `main.go` wires store + engine + window (stays at root — `mygo dev/build` build the project dir). `internal/syncjob` is domain logic with no `ui` import: `Job`/`Run`/`Ticket` model, `Store`, and `Engine` — the only boundary to Jira/ADO (`ValidatePAT`, `CheckJira`, `Sync`), and `State` (cursor + comment mappings, safe off the UI thread). `Fake` is the demo engine; `Seed` adds demo data. `fields.go` lists the ADO fields the engine can write: a job's Mappings select among them.
- **Real engine (`internal/syncer`)**: port of the source `runSync` — cursor → JQL (assignee filter, empty-result refetch) → sub-task backfill → parents first → per issue: detail, PBI/Task, WIQL match on the Jira key field, Done = comment only, Removed = reset first, create-then-move state, preserved fields + conflict comment, attachments, comments; checkpoint watermark per issue. Clients are built per run, so concurrent runs never share a PAT/log. Tests use in-memory fakes of the `jiraAPI`/`adoAPI` interfaces (`syncer_test.go`). Iteration (AutoPaths): issue in an *active* Jira sprint (Sprint field found via `/field`) → current weekly ADO sprint `SprintRoot\Sprint N`; anything else, including issues taken out of a sprint → backlog `SprintRoot`; no Sprint field → the run fails rather than moving everything to the backlog. A first run (no cursor) skips Done items without commenting. Deliberate fixes vs. the source: search fetches issuetype/parent (its parents-first sort was a no-op), WIQL values are escaped, the key field is configurable for both lookup and write, ADO project comes from the job.
- **Run options** (`syncjob.RunOptions`): every run starts with `preflight` (area/iteration paths via ADO classification nodes, Sprint field) and stops before any write if something is missing; `Engine.Check` exposes it to the editor's "Check in ADO". `DryRun` swaps in `dryADO` (reads pass, writes are recorded as calls with Response `dry run: not sent`, Status 0) and `readOnlyState`; dry runs are saved with `Kind` and ignored by `LastRun`. `Keys` reruns just those issues (Retry failed) without reading or moving the cursor. Cancel = cancelling the run's context (`a.cancels`), reported as "Cancelled".
- **Mappings** (`syncjob.Rules`, `/mappings`): issue type → work item type, status → state (backlog items and Tasks), priority; stored as JSON in settings (`mapping_rules`), `OrDefault()` fills gaps with the source's hardcoded values; travel to the engine in `Connection.Rules`. The shared user mapping (`shared_users`) is appended after a job's own users by `App.effectiveJob`, so the job wins.
- **HTTP (`internal/httpx`, `internal/jira`, `internal/ado`)**: `httpx.Client.Do` retries 429/5xx/network 3× (500/1000/2000ms), never other 4xx. `ado.Client.OnCall` reports every request, which becomes the ticket's API calls in the report. `ado.Host` is overridable for tests.
- **Logging (`internal/applog`)**: `main.go` calls `applog.Setup(mygo.PathLogs)` first; slog and std `log` go to `jira-ado.log` there (rotated to `.1` past 10MB) and stderr. The path is shown in Settings → Diagnostics. Log with context (`run`, `job`, `key`, method/url/status/elapsed/retries), never request bodies, headers, PATs or tokens. `syncer.Sync` and the `Async` wrapper recover panics via `applog.Recovered` (logs the stack), so a crash becomes a failed run instead of killing the app.
- **App icon (`internal/appicon`)**: three embedded icons; Settings → Appearance applies one at runtime with `mygo.App.Dock.SetIcon` (only after `WhenReady`). The Finder icon stays `resources/icon.png`.
- **Settings**: ADO org (from login), Jira URL/email, extra JQL, key field live in the `settings` table; the Jira token and PAT live in the keychain (`app.Keys`). `App.connection()` snapshots them per run; an incomplete one yields a failed run naming what's missing.
- **Storage**: `syncjob.Open` loads the SQLite DB (`<PathUserData>/jira-ado.db`, via `github.com/egoist/mygo/plugins/sqlite` — purego, no cgo; `mygo dev/build` bundle the dylib, `go test` downloads it once). `Store` keeps everything in memory for the UI and writes each mutation through in one transaction; failures go to `OnSaveError`. `NewStore` is the DB-less variant for tests. Schema changes are appended to `migrations` (PRAGMA `user_version`); never edit a shipped step.
- **Secrets**: the PAT never touches the DB. `internal/keychain` wraps `zalando/go-keyring` (macOS: `security -i` via stdin, so the PAT isn't in argv). `App` takes a `Secrets` interface; "Remember in Keychain" on login and the Settings switch decide whether it's saved. Keychain calls may block on a prompt — always through `Async`.
- **UI (`internal/app`)**: one file per page — `shell.go` (sidebar, topbar breadcrumbs, ⌘K palette), `login.go`, `dashboard.go`, `create.go` (4-step wizard; `draft.stepError` gates Next), `job.go` (tabs, runs table), `report.go`, `logs.go`. `widgets.go` has shared `page`/`stat`/`pill`/`kv` helpers and SVG icons.
- **Routing**: a `ui.Router` in `App`; `App.pages` is the route switch (`/`, `/jobs`, `/jobs/{id}`, `/jobs/{id}/report?run=`, `/create`, `/logs`, …). No PAT → `loginPage` instead of the shell. `section()` maps deep paths to the sidebar item.
- **Async**: `App.Async(work, done)` runs `work` off the UI thread and `done` on it. `main.go` sets it to goroutine + `win.Update`; the default runs inline so tests are synchronous. `work` must only touch copies (e.g. `job := *j`), never `App` state. Live progress: `Engine.Sync` takes `onProgress` (snapshots via `Run.Snapshot()`, called on the worker); `syncNow` hands them to the UI thread with `App.Post` (= `win.Update`, inline in tests) into `a.live[jobID]`, which the report shows as the `?run=live` entry until `done` saves the run and replaces the URL. Toasts from `done` go through `a.notice` (shown on the next frame) because `*ui.Context` can't be stored.
- **Immediate-mode views**: views rebuild from `App` state every frame (possibly several passes). Widgets bind to pointers into state; per-table `ListState` lives in `a.tables[key]`. Mutate collections being built via `.OnClick`, not inline.
- **Theme / layout** (modelled on native SwiftUI apps like TablePro): `internal/app/theme.go`. The content follows the System/Light/Dark setting (`theme` in settings; topbar sun/moon toggles it); dark content uses graphite `slate` greys. The sidebar is always dark (`sidebarTheme`) — a floating panel inset `sidebarInset` from the window, rounded, with traffic lights inside it. `c.SetTheme` applies to widgets built *after* it, so `View` sets the sidebar theme, builds the sidebar, then restores the content theme; the panel also sets `TextColor` because `ui.Sidebar` paints labels with the frame's last theme. Vibrancy is off (its material follows the system appearance). Toolbar = `capsule`/`toolButton`/`searchPill`; empty states = `emptyHint` with `keycap`s.
- **Tests**: `ui.NewTester` drives the view without a window (it renders the light system theme). Set `a.router.Transition = ui.TransitionNone` or clicks land on a sliding page. Labels like "Delete" can be ambiguous behind a dialog — press `ui.KeyEnter` for the alert's default button. `Tester.Image()` renders a PNG for checking layout.
- **Icon**: `resources/icon.png`, built from `design/logo/icon.svg` (`rsvg-convert -w 1024 -h 1024`). `docs/design-system.md` is the Linear palette research; the sidebar text colours come from it.
- Config is `mygo.json` (native projects have no `mygo.config.ts`).

## MyGo maintenance

`.agents/skills/mygo-maintenance/SKILL.md` has the MyGo-specific rules. Key points:

- Check APIs against the pinned source (`go list -m -f '{{.Dir}}' github.com/egoist/mygo`; `ui/doc.go`, `docs/ui/*.md`, `examples/`) or `go doc github.com/egoist/mygo/ui <Symbol>`, not memory — MyGo is `0.x` and changes between minors.
- Never store `ui.Element` or `*ui.Context` in app state or goroutines; use `ui.Handle` / `c.Key(...)` for persistent identity.
- Keep slow I/O (Jira/ADO HTTP calls) off the UI thread; publish results with `Window.Update`.
- For minor-version upgrades on `0.x`, read `docs/ui/migration.md` and use `go tool mygo migrate-ui .` (preview), then `-write`.
